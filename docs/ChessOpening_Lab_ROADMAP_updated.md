# ChessOpening Lab — последовательный roadmap

**Принцип:** прежде технический MVP на домашнем сервере; затем продуктовые аккаунты и монетизация; VPS — **отдельный публичный релиз**, а не инфраструктура MVP. Очередь анализа не внедряем до измеренной необходимости.

| Релиз | Состав работ | Критерий перехода |
|---|---|---|
| **R0.1 — Foundation** | Монорепо, React + FastAPI, Docker Compose home, PostgreSQL, Redis, Caddy, CI и quality gate | Воспроизводимый локальный/home запуск; health checks и базовые тесты |
| **R0.2 — Chess core** | Доска, полные правила, история, рестарт, смена стороны, оба пользовательских режима; подсветка возможных ходов союзной фигуры синим и вражеской красным | Playwright и unit-тесты правил, цветовой подсветки, preview и UI проходят |
| **R0.3 — Opening data** | Импорт именованных дебютов, позиции/транспозиции, потоковая обработка партий, основные продолжения, статистика дебютов | Контроль целостности, измерение охвата данных, воспроизводимый импорт |
| **R0.4 — Theory & tactics** | Проверенные идеи, планы сторон, ловушки и ошибки, интерфейс карточек | Все линии легальны, материал привязан к позициям, нет неподтверждённых утверждений |
| **R0.5 — Server analysis** | Stockfish EnginePool, Redis hot cache, PostgreSQL persistent evaluations, предварительный прогрев, защита от перегрузки | Проверены cache hit/fallback, занятость пулов, профилирование домашнего сервера |
| **R0.6 — MVP HOME** | Полная интеграция, адаптивность, опробование на тестовой группе, бэкапы, базовые метрики | Приёмочные AC-01…AC-10; отсутствие блокирующих ошибок |
| **R0.7 — Accounts** | Регистрация, вход, профиль, избранные дебюты и сохранение прогресса | Авторизация, изоляция пользовательских данных, тестирование сессий |
| **R0.8 — Paid SaaS** | PRO, стоимость 30 ₽ / $0.40 как гипотеза, платежи, автопродление, отмена, личный кабинет | Оплаты и webhook идемпотентны, entitlement сверяется на сервере, нет утечек платных данных |
| **R0.9 — Analytics & launch prep** | Метрики аудитории, конверсия/удержание, технический мониторинг, реклама после модерации, SEO | Дашборд, privacy и consent, нагрузочная проверка, восстановление бэкапов |
| **R1.0 — PUBLIC VPS** | Создать `deploy/vps`, compose VPS, домен/HTTPS, изолированная production БД, деплой проверенного релиза | Доступность, резервное копирование и нагрузочные тесты на целевом VPS; rollback-план |
| **R1.1+ — Scale** | При необходимости Redis-based queue, отдельный worker/сервер Stockfish, CDN, горизонтальное масштабирование | Только после реальной загрузки CPU, промахов кеша или отказов анализа |
| **R2.0 — Mobile** | PWA, затем Android/iOS, если есть подтверждённая активная аудитория | Экономическая и продуктовая валидация |

## Подзадачи каждого этапа в YouTrack

1. **Discovery/Architecture:** цель, ограничения, контракты, риски, проверяемые AC.
2. **Independent test design:** ожидаемое поведение, тестовые данные, негативные сценарии.
3. **Implementation:** минимальные проверяемые изменения без сторонних production-зависимостей сверх утверждённого стека.
4. **Review/Security:** анализ диффа, угрозы, лицензии данных и движка.
5. **Quality gate:** pytest; ruff check .; black .; pre-commit run -a (при наличии), TS checks/Vitest/Playwright, интеграционные и нагрузочные тесты при необходимости.
6. **Evidence and handoff:** изменённые файлы, принятые AC, как воспроизвести, известные риски.

## Правило перехода к VPS

VPS **не покупается и не настраивается сейчас**. Развёртывание на внешнем сервере планируется только после релизов R0.6–R0.9, когда имеются рабочий MVP, личные кабинеты/платежи (если публичная монетизация нужна с первого дня), тесты восстановления и подтверждённые ресурсные требования. Домашний сервер сохраняем как тестовую/staging среду.

## Масштабирование движка

Условие для будущей очереди и отдельного вычислительного сервера: устойчивые пики занятости EnginePool, рост p95 latency/доли `ANALYSIS_BUSY`, снижение hit ratio после оптимизации и прогрева. До этого Redis — только кеш, а ограниченный EnginePool не ставит запросы в долгую очередь.
